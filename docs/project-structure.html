Project Structure

Understand the Jen.js directory conventions and special files.

A typical Jen.js project follows this layout:

Special Files

FilePurpose
pages/**/app.tsxPage component — each resolved as a route
pages/**/layout.tsxLayout component — wraps child pages in its subtree
pages/api/*.tsAPI Route — exports HTTP method handlers (GET, POST, etc.)
_app.tsxGlobal application shell wrapping every page
_document.tsxCustom HTML document template
_error.tsxError boundary fallback component
middleware.tsEdge middleware interceptor (runs before routing)
jen.config.tsFramework configuration file

Route Resolution

Jen.js uses a filesystem-based router powered by the RouteScanner. Each directory under pages/ that contains an app.tsx (or app.jsx) file becomes a route:

  • pages/app.tsx → /
  • pages/about/app.tsx → /about
  • pages/blog/[$slug]/app.tsx → /blog/:slug

Dynamic segments use the [$paramName] folder convention. See Dynamic Routes for details.

Layouts

layout.tsx files are automatically discovered and nested. A layout at pages/layout.tsx wraps all pages, while pages/blog/layout.tsx wraps only pages under /blog/*.

See Layouts for more details.
